## 1. Вариант и условие задачи

**Вариант 32 — «Кухня ресторана».**

В ресторан приходят посетители, формирующие заказы из одного или нескольких блюд.
Официант принимает заказ и передаёт его на кухню. Каждое блюдо состоит из одной или
нескольких операций, для которых требуются повар и определённое оборудование: плита,
печь, гриль или рабочий стол. Повара выбирают доступные операции из очереди. Одна единица
оборудования одновременно используется не более чем для одной операции. Готовые блюда
собираются по номеру заказа. Официант может передать заказ посетителю только после
приготовления всех входящих в него блюд. Вместимость очередей кухни и зоны готовых блюд
может быть ограничена.

**Входные параметры:** количество посетителей, официантов и поваров; перечень блюд и
последовательности операций; количество единиц оборудования каждого типа; состав заказов;
интервалы появления посетителей; время приготовления операций; вместимость промежуточных
очередей; правила приоритета заказов.

**Отображаемые события:** приход посетителя, принятие заказа, создание операций, постановка
в очередь, получение поваром оборудования, начало и окончание приготовления, готовность
блюда, сборка и выдача заказа.

**Инварианты:** одну единицу оборудования использует не более одного повара; повар выполняет
не более одной операции; операция начинается только после выполнения предыдущих операций;
блюдо готово после завершения всех его операций; заказ выдаётся только после готовности всех
блюд и только своему посетителю.

**Завершение:** после закрытия приёма заказов и обслуживания всех принятых посетителей, либо
после явной отмены невыполнимых заказов, либо по прерыванию пользователем в режиме
неограниченного времени.

## 2. Сценарий: как сущности отображаются в программу

Программа работает в **одном процессе и одном потоке**. Одновременная работа участников
имитируется в цикле.

Модельное время идёт в минутах (переменная `now`). Всё, что должно случиться в будущем,
записывается в **список событий** (`events.c`): «повар 2 закончит операцию на 14-й минуте»,
«придёт посетитель на 17-й минуте» и т. п.

Главный цикл (`run` в `main.c`):
1. взять самое раннее событие и перевести часы на его время (с паузой для наглядности);
2. обработать событие;
3. дать всем свободным участникам взять новую работу (`everyone_works`): официанты,
   координатор, повара — по кругу, пока хоть что-то меняется;
4. проверить, не пора ли завершиться.

Когда участник начинает дело длиной N минут, в список событий добавляется событие
«через N минут закончу».

### Участники

| Участник | Тип данных | Поведение |
|---|---|---|
| Посетитель | `Visitor` | приходит и сразу решает, что закажет (`visitor_arrives`), ждёт официанта, ждёт еду, уходит |
| Официант | `Waiter` | принимает заказ, относит на кухню, разносит готовые заказы (`waiters_work`, `order_taken`, `order_delivered`) |
| Координатор кухни | функции в `kitchen.c` | проверяет, выполним ли заказ (`check_order`); берёт заказ в работу, создаёт операции и ставит блюда в очередь (`coordinator_work`); собирает готовые блюда по номеру заказа (`cook_done`) |
| Повар | `Cook` | берёт операцию из очереди, занимает оборудование, готовит, освобождает (`cooks_work`, `cook_done`) |
| Оборудование | `equipment_busy[тип][номер]` | номер повара, который его занимает, или −1 |

### Очереди

| Очередь | Кто кладёт | Кто забирает |
|---|---|---|
| `Q_HALL` — посетители в зале | посетитель | официант |
| `Q_KITCHEN` — заказы кухни | официант | координатор |
| `Q_COOKS` — блюда, чья очередная операция ждёт повара | координатор | повар |
| зона готовых блюд (`zone_used`) | координатор | официант |
| `Q_READY` — собранные заказы | координатор | официант |

Очереди — это обычные массивы: `queue[Q_HALL][i]` — i-й элемент очереди, `queue_len[Q_HALL]` —
её длина. Добавление в конец — `q_push`, удаление со сдвигом — `q_remove`.

Вместимость задаётся для очереди заказов кухни (`cap_orders`) и зоны готовых блюд (`cap_ready`).

Операции блюда выполняются строго по порядку, поэтому у блюда в каждый момент только одна
текущая операция (поле `step`). В очереди поваров лежат блюда; повар берёт текущую операцию
блюда.

### Путь заказа

```
посетитель пришёл → ждёт в зале → официант принимает заказ
  → координатор: невыполним? → заказ отменён, посетитель уходит
  → официант кладёт заказ в очередь кухни (полна — ждёт у раздачи)
  → координатор берёт заказ, создаёт операции, бронирует места в зоне готовых блюд,
    каждое блюдо — в очередь поваров
  → повар берёт операцию и свободное оборудование → готовит → освобождает оборудование
  → есть следующая операция? блюдо снова в очередь
  → нет? блюдо готово → зона готовых блюд → все блюда заказа готовы? заказ собран
  → официант забирает заказ и несёт своему посетителю
```

### Правила приоритета

Задаются параметром «Правило приоритета» (функция `order_before` в `kitchen.c`):
1. **FIFO** — кто раньше заказал, того раньше и готовят;
2. **VIP** — сначала заказы VIP-посетителей, внутри групп — FIFO.

Правило используется координатором при выборе заказа из очереди кухни и поварами при выборе
операции. Официанты подходят к посетителям в порядке прихода.

### Как соблюдаются инварианты

| Инвариант | Реализация |
|---|---|
| Оборудование — не более одного повара | повар берёт только единицу с `equipment_busy == -1` и записывает туда свой номер; после операции возвращает −1 |
| Повар — не более одной операции | работу получает только повар с `busy == 0` |
| Операция после предыдущих | в очередь попадает только текущая операция блюда; следующая — лишь после окончания предыдущей (`step++` в `cook_done`) |
| Блюдо готово после всех операций | блюдо готово, когда `step` дошёл до числа операций |
| Выдача после всех блюд и своему посетителю | заказ попадает к официантам при `ready == ndishes`; в `order_delivered` это проверяется ещё раз, при нарушении программа завершается с ошибкой |

Чтобы кухня не встала навсегда (зона готовых блюд забита блюдами разных недоделанных
заказов), координатор при приёме заказа **бронирует** места в зоне под все его блюда и не
берёт заказ, если мест нет. Официант, ждущий у раздачи, может отнести собранный заказ, чтобы
освободить зону.

**Невыполнимый заказ** координатор явно отменяет с причиной: на кухне нет поваров; нет нужного
оборудования; блюд в заказе больше, чем мест в зоне готовых блюд.

## 3. Пользовательский интерфейс

При запуске выбирается сценарий, затем можно изменить любой параметр с клавиатуры
(в скобках — значение по умолчанию, Enter — оставить, неверный ввод запрашивается заново):

```
Сценарии:
  1 — Обычный вечер
  2 — Час пик, тесная кухня
  3 — Сломан гриль
  4 — Без ограничения времени (Ctrl+C)
  Выберите сценарий [1]:
Изменить параметры сценария? [y/N]:
```

Меню (блюда, их операции, оборудование и время) задано в программе (`config.c`). Состав
заказа — от 1 до «максимум блюд в заказе» случайных блюд меню, интервал прихода посетителей —
случайный в заданных пределах (`rand`).

Перед моделированием печатаются параметры и меню. Потом каждое событие — одна строка:

```
[время] Участник: что произошло
```

с номерами заказов, названиями блюд и операций, номерами оборудования и заполненностью
очередей, например `(3/5)`. Между модельными минутами делается пауза (`nanosleep`). В конце
печатаются итоги.

## 4. Запуск и завершение

```
make
./restaurant
```

| Сценарий | Особенность | Завершение |
|---|---|---|
| 1. Обычный вечер | 12 посетителей, FIFO | после 12-го посетителя вход закрывается; конец — когда все обслужены |
| 2. Час пик | 20 посетителей, по одной единице оборудования, маленькие очереди, VIP | так же; по пути заполняются очереди |
| 3. Сломан гриль | гриля нет | заказы с блюдами на гриле отменяются; конец — когда все обслужены или ушли |
| 4. Без ограничения | посетители приходят бесконечно | только по Ctrl+C |

В любом сценарии **два варианта завершения**:
1. **по окончании работы**: вход закрыт, каждый посетитель обслужен или ушёл из-за отмены;
2. **по прерыванию**: Ctrl+C. Обработчик сигнала `SIGINT` только ставит флаг, главный цикл
   его видит, останавливается и печатает итоги.

Все данные хранятся в массивах фиксированного размера: до 1000 посетителей, 50 официантов и
поваров, 20 единиц оборудования каждого типа. В сценарии 4 после 1000-го посетителя вход
закрывается.

## 6. Тестирование

Запуск всех тестов:

```
make test
```

Тесты записаны прямо в `Makefile`. Для каждого теста в папке `tests/` лежит файл `ИМЯ.in` —
ввод для программы: ответы на её вопросы, по одному в строке (сценарий, «изменить
параметры?», затем параметры в том порядке, в котором их спрашивает программа; задержка 0,
чтобы тест шёл быстро).

`make test` запускает программу с каждым вводом, сохраняет вывод в `tests/ИМЯ.out` и через
`grep` проверяет, что в выводе есть нужная строка. Если строки нет, `make` останавливается
на этом тесте. Тесты `interrupt` через секунду прерываются по Ctrl+C.

| Тест | Что проверяет | Ожидаемые строки |
|---|---|---|
| `01_normal` | обычный вечер, 12 посетителей | пришло 12, не обслужено 0, ресторан закрывается сам |
| `02_full_queues` | все приходят сразу, очередь кухни — 1 заказ, зона — 3 блюда | «очередь заказов кухни заполнена», «в зоне готовых блюд нет места» |
| `03_no_equipment` | нет оборудования | «нужно оборудование», отменено 10 |
| `04_no_cooks` | нет поваров | «на кухне нет поваров», отменено 8 |
| `05_small_zone` | зона готовых блюд на 1 блюдо | «блюд больше, чем мест в зоне готовых блюд» |
| `06_one_of_each` | 1 официант, 1 повар, по 1 единице оборудования, VIP | пришло 15, не обслужено 0 |
| `07_many` | 1000 посетителей | пришло 1000, не обслужено 0 |
| `08_bad_input` | неверный ввод: `abc`, `9`, `-5` | сообщения об ошибке ввода, пришло 12 |
| `09_interrupt_unlimited` | режим без ограничения + Ctrl+C | «получен сигнал прерывания», итоги |
| `10_interrupt_scenario` | обычный сценарий + Ctrl+C | «получен сигнал прерывания», итоги |

Результат: все 10 тестов пройдены, `make test` заканчивается строкой «Все тесты пройдены».

## 7. Структура программы

| Файл | Назначение |
|---|---|
| `restaurant.h` | константы, типы данных, общие переменные, объявления функций |
| `main.c` | главный цикл, обработка Ctrl+C, итоги |
| `config.c` | меню, готовые сценарии, ввод и вывод параметров |
| `events.c` | список запланированных событий |
| `hall.c` | посетители и официанты |
| `kitchen.c` | координатор кухни и повара, правило приоритета |
| `util.c` | вывод событий, случайные числа, пауза, очереди |
| `Makefile` | сборка (`make`) и тесты (`make test`) |
| `tests/*.in` | ввод для тестов |

Используются функции libc (`printf`, `fgets`, `rand`, `srand`, `time`, `signal`) и системный
вызов `nanosleep`.
